# Resume wording and interview evidence

以下是项目简历候选文案；指标只对应本仓库记录的本机实验。

**KVRPC：C++17 RPC 通信与持久化 KV 缓存服务**  
技术栈：C++17、Linux、TCP、poll、线程池、连接池、LRU、AOF、CMake

- 实现类型化 RPC 方法注册与分发，支持参数序列化、异步 future 调用及远程错误返回；通过连接池复用 TCP 连接，处理部分读写、请求超时与异常连接回收。
- 设计固定线程池与有界任务队列，实现过载拒绝和连接租约生命周期管理，避免请求积压导致线程无界增长及连接池销毁后的悬空访问。
- 实现就绪请求批量提交，将同轮写操作合并到一次 fsync 后确认；在本机 WSL2、32 并发、256 B 值、50% 写入的三轮对照实验中，吞吐量中位数由约 474 提升至 3,591 ops/s，P99 由约 93 ms 降至 12 ms。
- 构建用户资料 RPC 查询与缓存回填示例，验证缓存命中和主动失效；覆盖批内读写顺序、异常协议、日志容量上限及进程重启恢复，并通过内存／未定义行为与线程 Sanitizer 检查。

## 面试主线

1. **问题**：逐条 fsync 让串行事件循环被磁盘等待占用，并发请求排队。
2. **测量**：使用真实 TCP 客户端，固定值大小和读写比例，对比同一二进制的 always/group 模式；统计吞吐量、P99 和 AOF 同步次数。
3. **方案**：收集同轮就绪请求，按序写日志，共享一次 fsync，再按序执行缓存操作与生成响应。不额外等待凑批。
4. **正确性**：批次落盘完成前不回复；失败后拒绝继续服务；同一连接按请求顺序执行，跨连接只有服务端选定的串行顺序。
5. **取舍**：磁盘仍在事件循环中同步执行，混合批次的读请求仍会等落盘；单并发没有明显收益；批量提交不等于多操作事务。
6. **恢复边界**：LRU 读访问未写日志，恢复后驻留键可能改变，已淘汰键可能重新出现。缓存保留独立数据源，示例使用版本化键与主动失效，不能把它描述成无损持久化数据库。
